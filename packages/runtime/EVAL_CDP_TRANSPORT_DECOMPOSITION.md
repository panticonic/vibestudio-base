# Explicit CDP transport for confined imported programs

Inventory before edits:
- `packages/cdp-client/src/worker.ts` owns the common raw CDP connection, browser implementation and WebSocket handshake. Its ambient WebSocket/fetch discovery fails inside private Eval library scopes.
- `packages/cdp-client/src/browser.ts` and `src/index.ts` export the same worker implementation to panels/default Node consumers; package exports select worker/browser variants. The handshake must remain shared, with browser-native and worker fetch-upgrade behavior retained.
- `packages/eval/src/execute.ts` and Host `packages/shared/src/evalConfinement.ts` intentionally give imported/guest programs a private allowlisted global. Removing confinement or adding ambient network globals is incorrect. Native runtime objects are explicit capabilities supplied to the guest.
- `packages/runtime/src/shared/workerd.ts` creates the native workers facade in panels, workers and DO/Eval kernels. It can acquire an inspector endpoint with the existing approval-gated RPC and bind a socket opener to that exact URL/token.
- `packages/runtime/src/panel/cdpAutomation.ts` acquires panel endpoints itself but loads CDP client code into a confined hosted realm. Its existing preferFetchUpgrade option cannot supply the missing transport. It needs the same endpoint-bound native opener.
- `packages/testkit/src/workerd-profile.ts` is the official raw inspector/profile helper. Its implementation, CPU-profile collection, save/cleanup and profileDO composition remain shared; only connection acquisition changes.
- Host `workerdInspectorService.ts`, inspector/panel bridges, `cdpGrants.ts` and `egressProxy.ts` already mint, bind, validate and redeem short-lived exact-target grants. The native socket opener retains this path and does not authorize arbitrary network endpoints. There is no need for a second profiling implementation or an additional Host profiling service.

Implementation: factor the existing socket handshake into one small CDP transport module with an explicit platform parameter. The native runtime supplies its platform only through an opener bound to the endpoint/token returned by its own gated RPC. The connection and BrowserImpl accept that opener. Unconfined panel/DO direct imports keep the existing ambient transport path; confined Eval imports use only the capability. No global network endowments or transport hooks enter the guest.

Validation must exercise the actual CDP handshake and profiler messages with real CdpConnection, including a confined VM with neither fetch nor WebSocket; test substitutions, cancellation and cleanup. Existing fake-CDP profiler tests are insufficient. The live smoke must then use the official profileWorkerd helper in the actual managed Eval, followed by cold/warm Natlang describe investigation without paid model calls.

Implemented verification: 89 existing CDP connection/browser tests and 26 panel-mediated tests pass. New regression bundles the actual CdpConnection, BrowserImpl and official profileWorkerd helper into a Node VM with neither fetch nor WebSocket. A real local WebSocket server exchanges CDP profiler messages, and the official helper persists the resulting standard CPU-profile artifact through the normal profile store. Both native WebSocket and native worker-style fetch-upgrade capabilities pass. The worker-upgrade case also connects the actual confined BrowserImpl through native panel mediation. Exact URL/token substitution, pre-aborted connection and permission-denial negatives pass. No real CPU measurement is claimed by this transport regression: live workerd CPU sampling remains required after the successor kernel/release build.

Actual managed Eval correction (2026-11-23): the first live successor probe still failed before collecting samples. Host `EvalDO.ensureRuntimeSupport` loads both hosted/panel factories in private library scopes; a factory returned by that loader is not a privileged realm. Consequently the previous VM test's native-created runtime factory did not model the actual assembly. The common handshake now lives in Host SDK `@vibestudio/rpc/protocol/cdpSocket`, requiring an explicit platform argument (no ambient SDK network authority). Base's unconfined default explicitly supplies its own caller realm. Host EvalDO records successful native endpoint RPC replies per active execution and injects the endpoint-bound kernel opener into both private factories. The old selective raw-fetch private-module endowment is removed.

The kernel opener is one-use, checks exact issued URL/token plus active execution identity, closes on cancellation/completion, and forwards only a frozen null-prototype socket facade and plain text protocol events. Native targets/constructors never cross the boundary. Cancellation permits terminal close/error notifications while the owner is still active to settle pending commands; nonterminal messages and all completed-owner callbacks are suppressed. Native listeners and abort handlers are released on close. The actual private factory kernel regression reproduces the prior failure and exercises real inspector and panel createCdpAutomation/BrowserImpl connections, substitution/duplicate rejection, cancellation, completion and sanitized events. SDK typecheck, 118 Base regression tests and eight Host kernel/outside-content tests pass. Live CPU measurement remains pending the rebuilt combined release.
