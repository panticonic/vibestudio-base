# Model-owned operational composition (pre-edit inventory)

This batch addresses four concrete open-user-goal root coordinators. The wider census has 116 descriptors (98 TS and 18 NL at the preceding source); those counts indicate availability, not that every TS function is wrong. The remaining families are still under review.

* `workOnProgramRunGoal.ts` selects a program, fixes inspection/review order, caps the selected continuation at two samples, and decides when signing occurs. Its named semantic children select program/sample/continuation/signing and the mounted `reviewer` evaluates runtime evidence. Mounted `runtime` is `skills/open-program-run`: native catalog inspection, revision-bound run, retained output read and signing. These exact authority helpers stay TypeScript.
* `workOnEvalHandoffGoal.ts` fixes observation order, retry/review branching and optional retention. Semantic children choose job/attempts/disposition/retention; mounted `journal` is `skills/open-eval-handoff`, mounted `reviewer` is `skills/sandbox/recovery`. `confirmedEvalResult` mechanically joins independently observed digests/readback; `applicationResult` preserves native values. These mechanical helpers and the native exact retry grant stay TypeScript.
* `workOnAuthoringGoal.ts` fixes two discovery/review attempts and stage branching. Mounted `discovery` is `skills/open-authoring-goal`, `reviewer` is `skills/natlang-authoring`. Discovery has a named semantic selection hierarchy; confirm and handoff are native authority boundaries. Semantic stale-source reconsideration and requested retention belong to the root model, not a fixed two-pass loop.
* `workOnTerminalApp.ts` fixes inspection/plan/application/final verification into one repair attempt. Existing named inspection, plan/scope, diagnostic explanation and verification children provide the hierarchy. A new exact TypeScript edit helper forwards issued source revision and before/after edits; only that helper receives the existing native edit grant. The separate SST iteration successor removes artificial one-shot restrictions while preserving actual CAS and the explicit coauthor-movement stop.

`recoverOperatingHandoff.ts` is also an authored consumer of the eval root; its import changes to the actual NL module, preserving its separate handoff semantics. The first actual-loader run caught the missed extension and was stopped after confirming the same TS2307 across the first three cases; it was not a test pass.

Shared consumers: `skills/open-user-goal/entries.json` and its existing generator register each root; `entrypoints.ts` emits exact callable/program/input/default provenance. `natlang.json` owns mounts and service scopes. SST native fixtures and Host application entry binding derive actual entry metadata from that registration; goal IDs/text/splits and result types remain unchanged. Scripted loader tests must use the new NL callable API and prove actual helper visibility and native binding, not merely inspect prompt strings.

No root generator was found beyond the canonical entries generator: historical V14 lowering metadata records past changes, rather than creating current source. Root instructions describe their own returned values, evidence and effects. No fixture examples, expected answers, forced route or mandatory all-helper budget are added.

These are joint application programs, consumed by the shared Natlang program loader across Node/Workerd/SDK targets. Compiler/engine code, managed llama/wllama/Python/SGLang inference routes, credential transport and training loss do not implement these application decisions and are unchanged. Existing program loading admits NL/TS/JSON/Markdown; contextual NativeSkill knowledge is already supported by companion `skills/*/SKILL.md`, so no new knowledge loader is needed.
