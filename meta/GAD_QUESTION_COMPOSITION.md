# Conditional durable-question composition

Inventory before edits: public `reviewDurableQuestion.ts`, its registered entry and generated registry, question/history and roster judgment types, the exact `readMessages`/`readMembers` native boundaries, both pure interpretation leaves, `natlang.json` scoped-service bindings and the authoritative GAD decomposition guide. The old TS entry unconditionally read and judged membership even when the user only requested quoted text or conditioned membership on a question that did not exist. Its public result could not honestly express unrequested membership or absence of a roster receipt.

The public entry is now `reviewDurableQuestion.nl`, with the same callable, arguments and result type name. It owns goal-dependent semantic composition through independently useful `reviewQuestion` and `reviewParticipant` lambdas. Their existing TS readers own exact native evidence acquisition. The root decides whether membership is requested under the actual conditions, preserves native question/participant findings and returns an honest answer without a prescribed tool sequence or fixture classifier. The returned participant may explicitly be not-requested and its receipt null. `evaluateRoster` retains its original strict judgment type and behavior: an inactive identity does not become absent. No scopes or authority grants change.

The installed skill source's decomposition guide is updated so refresh cannot reinstate the always-read-both contract. Entry metadata and its existing generated output agree on the actual NL source. No goals, IDs, splits or native service signatures change. SST's report verifier must separately accept omitted roster evidence only for genuinely unrequested membership, while validating any provided native receipts and every required membership finding. That consumer adaptation is not part of this Base commit and is required before activating this changed public result contract.

Actual checks: `vibe-gad-question-composition-20261125c` passed four real Base gateway/evaluator controls (20.8s,2.5GiB). The actual authored sources are parsed/compiled and executed against scripted model turns and injected exact native history/roster readers. Requested current membership acquires its actual roster and receipt; conditional question absence, quote-only and incomplete-history goals do not acquire membership and return null/not-requested. Exact native history/channel/question/member values and reader/turn counts are asserted. No inference, provider connection or fixture answer enters production. The Node host runs the actual Workerd SDK evaluator; this is not an independent standalone-Node engine or live Workerd server qualification. Full-template typecheck remains unchecked.

Earlier check evidence is retained: the first inherited 768MiB inner heap was insufficient during dependency loading (not a product/cgroup OOM); a realistic1900MiB heap/4GiB expected/5GiB hard check then reached a projection YAML CommonJS resolution failure before tests. Selecting the same installed YAML2.9 official ESM export in the Host-owned test projection allowed the final genuine checks; no parser mock or source dependency installation was introduced.
