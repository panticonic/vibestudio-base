# Shared goal-review mode

Actual wave0063 reviews introduced unrequested repair and unconditional-send obligations. The shared observed-content review now requires interpretation of the literal goal's query, diagnostic, proposal, conditional-execute or execute mode. This supplies no reference route, desired outcome, test words or new actor authority. Native checks, requested returns, retained artifact and mandatory independent review remain unchanged. A genuine action request cannot be completed by a report; a diagnosis need not repair an unrelated system.

Inventory: `packages/application-outcomes/observed-content-review.ts` is the shared synchronous projection and asynchronous binder. Its callers include all SST open-goal content-review families plus Google/News/Personal/System/Examples verifiers that import the package; all inherit the corrected rubric without changing bytes in their native evidence. Host `scripts/lib/observed-content-admission.mjs` binds the exact proof observation/artifact fields, expected goal and return requirement; it accepts a nonempty source-authored rubric rather than inventing its own. `workflowReviewer` and the Natlang `modelOracleJudge` transport that bound input; Python and Node completed-reassessment validators preserve rejected reviews separately and require a genuine accepted bound review. They need no schema or permission change. This is application outcome-review guidance, not an execution-engine prompt/protocol change.

Domain-specific source semantics remain in the SST companion change: object/participant identity versus membership lifecycle revisions, exact-room recipient resolution and send permission versus a board owner, and accepted artifact identity versus unobserved file contents. No successful outcome is inferred from guidance alone.
