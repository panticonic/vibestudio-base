# Canonical decision scoring through the model gateway

2026-11-24 inventory before edits. The concrete defect is lost conditioning and capture, not model behavior: a canonical Natlang DecisionRequest enters driver.decide, but the driver rebuilds only Pi context/candidates. The gateway contract/schema accepts only that reduced shape, scoreItem retranslates Pi context and drops historical thinking, and ModelGatewayDO/driver rebuild results without open/reasoning echoes or native capture. This can score a reasoned/open readout as an unreasoned/closed one.

All product consumers found: packages/natlang/src/driver.ts; packages/model-gateway/src/contract.ts and transparent client.ts; workers/model-gateway/{scoreItem.ts,ModelGatewayDO.ts}; packages/model-catalog/src/localModels.ts extension response schema; System local-models ScoreItem/ScoreResult public declarations and its existing unchanged JSON transport (owned by installed_deployment_mode); skills/workspace-dev/WORKERS.md. Relevant tests cover driver, schema, worker, item conversion, client cancellation and capture. No other product gateway.score caller was found. Generation's Pi context translation is separate and remains in use. Model capture records the complete request/result and original failed provider evidence.

Canonical mechanism: the gateway's scoring input uses Natlang DecisionRequest directly beside the authorized model/turn identity. It does not round-trip scoring history through Pi. The worker uses the vendored canonical batchScoreItem and scoresFromBatchResult. Missing requested reasoning/open echoes are errors, never closed/unreasoned fallback; native captures survive every result boundary. Split tokenization and exact reasoning IDs use the SDK's existing defaults/opt-outs, not a new policy. Caller metadata remains capture evidence and is not implicitly model instructions. Explicit privileged context is forwarded as its canonical transport field.

Local-models response schema currently uses passthrough and therefore retains unknown wire fields; its typing/validation must declare canonical echoes/capture and optional token counts, rather than falsely treating canonical optional tokens as required. Native_state_imports, when present, remains telemetry. System owns the raw HTTP transport and canonical public type exports; it already forwards the whole JSON unchanged. Base owns request validation, authorization, item rendering, output validation, native capture and driver propagation.

Engine scope: this repair is at VibeStudio's gateway before/after the local-models scorer. Managed llama-server, in-page wllama, Python native/SGLang scorers and Core's standalone scoring already consume canonical DecisionRequest/batchScoreItem and are not traversed by gatewayDriver (the gateway's hosted-provider scoring branch explicitly rejects decision-unsupported). No engine implementation is changed here; Core's existing canonical renderer/echo checks are reused rather than cloned. The original Workerd OOM investigation remains independent and open.
