# Deployed interface ownership review

| Responsibility | Implementation |
| --- | --- |
| Select the actual installed unit and exact requested boundary | A typed Natlang branch separates an agent declaration, worker service, and trusted extension even when their display titles or requested features overlap. |
| Read a routed architecture owner | Compose the installed Architecture hierarchy for assigned durable provider routes; it uses actual workspace resolution and authored declaration readback without running the domain method. |
| Compare working declaration, registered artifact, and retained approval | Typed Natlang selects what is established for the exact source and scope. Crisp service code obtains current VCS bytes, read-only operational metadata and, when available, exact immutable build metadata. It exposes no invocation, build, lifecycle or publication operation. |
| Decide whether an update proposal can be carried forward | Typed Natlang reports allowed read-only review and distinguishes an actual deployed claim from a declaration-level comparison. A stale approval, mismatched receiver, forbidden widening, or required but absent exact artifact produces a held finding. |
| Save an authorized local reviewer handoff | Scoped scratch writer records the actual inspected surface and exact approval. Independent verification reopens repository files and ownership metadata, checks scratch bytes, and confirms protected heads did not change. |

This cohort uses small retained review instructions and independent existing native reads. A creator-scoped case allocates an owned disposable headless channel solely for receiver resolution. The cohort does not launch agents or extensions, ask an agent to operate, invoke domain methods, change authority, or publish. Existing architecture, workspace-dev and runtime inspection scopes remain in force. Engine, collector and training artifact formats are unchanged.
