# Owned incident and release continuity

The entry takes a user goal. It identifies the requested operation from an owned
workspace docket and chooses the installed incident or release hierarchy. The
docket contains current source evidence and authorization limits.

| Work | Natlang responsibility | Exact Vibestudio mechanism |
|---|---|---|
| Identify the operation | A dedicated function binds the user's concern to a unique local docket and considers its authority. A missing or ambiguous match stops here. | Scoped list and read over the owned evidence store. |
| Coordinate incident roles | The installed incident hierarchy assigns impact and recovery responsibilities, evaluates the evidence for each role, and synthesizes the two retained assessments. | Same owned worker, append and independent read APIs as the existing role workflow. |
| Continue a release | The installed release hierarchy interprets the previous and current gate sets, verifies continuity after restart, and writes the next assessment. | The owned worker's real restart and persisted checkpoint reads. |
| Report and retire | The parent preserves the returned handles, decision and evidence. It closes the resources issued to the current operation and states the local outcome. | Exact resource cleanup and independent observations, with harness cleanup on failures. |
| Check the result | The expected role decisions, evidence assignments, restart history and cleanup are private to the reference checker. | Existing owned-operations oracle, bound docket readback and native call evidence. |

The runtime bindings apply to all model providers through the same hosted
workspace boundary. The standalone serving engines never load these scoped
Vibestudio services. The learner consumes supervisor-verified trajectory IR.
