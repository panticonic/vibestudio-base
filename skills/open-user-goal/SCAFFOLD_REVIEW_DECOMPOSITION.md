# Prepare and inspect an owned scaffold

## Native mechanism inventory

- The existing scaffold matrix checks React and Svelte panels, stateless
  and agentic workers, packages, skills and content projects. It calls
  installed workspace-dev `prepareProjects`, confirms VCS publication,
  then invokes a canonical Build V2 verifier. The open-goal family starts
  from the user's product outcome, chooses the native scaffold, prepares
  an isolated draft, and independently reads back exact generated files.
  Build and deployment need a separate authorization.
- The installed workspace-dev generator owns project kind/name validation,
  authority manifests for executable units, client ABI selection, template
  token application, module preflight and native semantic VCS edit. Reuse
  these exact functions. Retained build diagnosis uses different inputs.
  Workspace assembly analyzes existing, independently staged package source.
- Independently verify manifest kind/exports/authority and exact own VCS file
  bytes using the native repository ID and working state. Never infer
  readiness for deployment from a source preflight. Check allocated output
  names and report a hold when target ownership, authority or installed
  template availability changes.

## Natlang stages

1. Identify the exact product brief and owned work scope, then inspect
   available scaffold/runtime options.
2. Choose the appropriate typed scaffold and exact allowed destination.
   Require the executable authority envelope where the native generator
   requires it. Use a read-only disposal when the user just wants guidance.
3. Recheck exact target and working revision; prepare only the approved
   draft. Read each retained repository back from the actual native VCS
   state, then report truthful readiness and any remaining verification.
