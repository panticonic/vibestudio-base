# Review an already-staged Examples composition

## Mechanism inventory

- The installed Examples template candidate skill reads an exact update offer
  and prepares the native separate update context. The open generic migration
  family already chooses an offer, handles stale/disagreeing deployment data,
  stages a candidate and preserves the current deployment. This family starts
  later, with two already staged local semantic VCS review states. It does not
  create an update offer, resolve a native update, or publish.
- The production workspace root bootstrap uses
  `templateRepositoryOwners` and `mergeTemplateManifests` from
  `@vibestudio/workspace/templateManifestMerge`, then
  `composeTemplateLayers` from `@vibestudio/workspace/templateComposition`.
  Development template checkouts use the same manifest merge and ownership.
  Use the shared exact mechanisms for preserved parent units, explicit
  whole-unit replacement, conflicting owners, duplicate declarations, and
  epoch differences. Use the production `resolveTemplateClosure` shared by
  checkout and workspace template publication for relevant package closure.
  Exact snapshot acquisition is supplied by the owned VCS rehearsal; no Git
  fetch, remote registry or whole template deployment is involved.
- The installed Examples manifest and actual named unit package manifest are
  read at protected semantic main. Minimal authored candidate files are
  imported via the existing VCS snapshot path into the owned working context.
  The verifier checks exact staged repository IDs and bytes, then rereads the
  newer working head and unchanged protected main independently.
- Scratch evidence uses `bindScratchHandoff`, bounded byte readback and new
  artifact accounting. The scratch authority is explicit, and its receipt
  binds the exact selected candidate and composition digest.
  Authored snapshots and scope never authorize real installations.

## Natlang stages

1. Discover the authorized review, disambiguate its newer owned candidate from
   the retired alternative, and read the exact independently stored Examples unit.
2. Inspect the native owner/manifest/closure composition. Ground each finding
   in the returned effective repository paths, owners or exact native refusal.
3. Decide whether to record the approved evidence, explain in chat, or hold
   for invalid ownership, closure, epoch, or declaration. Recheck the
   working semantic head before acting. Capture changed revision as a hold.
4. Stage only a private local handoff. Read back the exact artifact and scope,
   and preserve both the protected deployment and current owned review.
