# Activate an owned automation from retained authorization

| Stage | Implementation | Scope |
| --- | --- | --- |
| Discover the request | Typed NL over exact owned evidence | Join the requested operation, owner and approval edition. Retired consent and preview do not authorize creation. |
| Draft the operation | Installed automation planner | Interpret cadence, executor, continuity and operations through the existing hierarchy and conversion. |
| Decide activation | Typed NL | Resolve existing, ambiguous, withdrawn, pending and authorized cases. |
| Activate | Crisp owned service | Check the exact consent revision and call the native Missions launch and retry. Intervals start far in the future. Manual activations have no occurrence until requested. |
| Confirm | Typed NL over independent native and scratch readback | Compare exact owner, charter, revision, next occurrence, single activation and empty run ledger. |

Existing recovery goals concern scheduled definitions that already exist. This family exercises creation from a retained owned decision and exact retry. No fixture runs execute, and the execution definition contains only a fixed local script.
