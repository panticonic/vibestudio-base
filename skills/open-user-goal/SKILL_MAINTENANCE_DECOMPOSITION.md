# Maintain one reusable workspace skill from retained evidence

## Exact mechanism inventory

- The pinned `self-development` child-eval and dirty-semantic-state tests join
  native run identity to exact working source. The skill-oriented subsets of
  `skills` and `natlang-skills` verify installed instructions and typed behavior.
  These scenarios cover local reusable Natlang contract maintenance after a
  retained native witness. They do not launch an isolated host, grant child
  authority, run a model, invoke a real device, or publish.
- Base `skills/natlang-authoring/reviewProgram` already reviews signatures,
  nested helper paths, compiler diagnostics and declared authority. System
  Testing's `readAuthoringProgram` converts actual `natlang.describe` results to
  exact review records. The fixture reuses that boundary and the shared
  Natlang authoring callable. Runtime suffixes and service selectors come from
  the compiled package, not from text heuristics.
- Actual `createEvalExecutor`, `eval.receipt` and the existing owned eval
  conventions bind finite, read-only compiler checks to retained native
  execution identity. A fixed authored eval does not execute model-written
  code. It returns the declared callable contract and exact regression
  observation. An independent read of the same terminal receipt must match.
- Semantic VCS performs all source writes through `vcs.edit`, with stable
  repository/file identifiers and an exact `expectedWorkingHead`; no commit
  or publish is necessary for the isolated working candidate. The package and
  a related archive are fixture-owned. The compile oracle reads back the
  actual working files/shape after the edit, confirms the addressable exact
  helper signature, protects every unrelated file, and leaves main untouched.
- Existing open authoring generates review plans and scratch handoffs. Existing
  native action recovery attests tool effects and retry safety. The new goals
  require a retained contract regression, a real local skill patch when
  warranted, and after-decision compile/readback. A compile witness establishes
  a typed contract and callable topology, without measuring model behavior.

## Natlang stages

1. Locate the exact current skill and read its source and retained eval
   identity through separate typed stages. The original user goal sets intent.
2. Ask the installed authoring reviewer to interpret the current contract.
   Decide whether the recorded evidence and current edit authority still
   describe the same skill revision. Holds require grounded reasons.
3. If the evidence and scope permit a local repair, draft the changed files
   in a dedicated lambda. Authoring decisions are model policy. The crisp
   binding accepts bounded text for the assigned Natlang child and commits
   only that local working edit through semantic CAS.
4. Re-read the actual compiler and source evidence after the decision.
   Independently check expected signatures, child paths, retained original
   witness, authorized dispositions and source state. Capture requires all
   effects and typed values through their actual callable ancestors.
