# Retained local execution readiness and width

| Decision or mechanism | Representation |
| --- | --- |
| Identify the current user-owned machine, model, and desired task shape | Typed natural language selects current observations and distinguishes a server label from the actual installed and selectable model. |
| Interpret product inventory | Mount and call the installed System localModelReadiness hierarchy. Its stock policy determines catalog lifecycle and classifies a native inventory fault. Use the installed native model-catalog wire parser for the captured local-model rows. |
| Join execution capacity evidence | Typed natural language checks exact machine, boot, config, provider and model identity. It compares witnessed completed parallel work at the requested context size with advertised capacity and with visible provider tool support. It distinguishes a compatible startable model from loaded/attested execution. |
| Leave a permitted local handoff | One narrow native scratch writer preserves the actual captured evidence and verified disposition without sending any message, changing local settings, or touching any credential. |
| Verify independently | Model-free System Testing reopens FS records and exact output bytes, recalculates outcome from separate retained scope and witness data, checks the protected working and main head, and checks exact Natlang child call and effect references. |

The finished managed world uses disposable workspace files representing retained, incident-owned observations. Server/inventory wire evidence has the actual native shape. Width witnesses are authored retained receipt fixtures with explicit machine, boot and configuration identities. This deliberately avoids starting or cold-probing any local server, reading external credentials, opening a socket, or using any model, hardware or lifecycle operation. It tests whether a candidate can reason correctly over the captured evidence. It does not measure hardware throughput or claim independent live model availability.
