# Android runtime audit

The workspace goal callable selects a passive native audit when the user asks
for evidence about an assigned Android target or its current application. The
scope reader binds the original goal to the real managed target and operation.
The planning lambda decides whether the user requests device evidence alone
or an application observation. It preserves the original goal and coordinates.

The installed System audit owns the target and application observations. Its
target review and runtime review are separate lambdas. A missing target stops
the branch. A running process and screenshot support an application statement.
Workspace readiness would require separate workspace evidence.

System Testing owns the test emulator selection and an independent receipt
check. The training exporter binds the actual calls and service results to the
receipt. Installation, pairing, application launch and user data reset are
separate goals. Source fixtures supply controlled native observations. Managed
execution requires an assigned disposable emulator in the declared app state.
