---
name: private-project-evidence
description: Interpret current source authorization and actual private document state without confusing semantic review with native authority.
---

Requirements describe what the material needs to cover; safety evidence constrains how to express it. Local approval limits allowed effects. Retired records can explain a change but do not authorize the new edition. A destination already owned by another project is not empty because the requested title is similar.

A scope receipt binds the source revision and selected facts. It is not a completed artifact. Native preparation and writes return the actual working head; successful own writes legitimately advance that head. Review the retained document bytes and navigation, distinguish a repairable finding from missing authority, and preserve supported content through revision. A ready semantic review does not manufacture approval, a local commit event or a successful current-head comparison. Conversely, an uncommitted requested draft is a real deliverable and should not be committed merely to sound complete.

Use the application's actual project pointer and local event to identify the resulting work. Source signatures, clean state and familiar filenames alone do not establish useful document content. A private commit never implies publication or permission to notify another participant.
