# Extension release verification

| Responsibility | Implementation |
| --- | --- |
| Identify the user's assigned extension and intended review | The root Natlang function calls a typed discovery branch for the owned review assignment, then invokes the installed extensiondev source and runtime review as a child. |
| Compare working and protected packages | A narrow TypeScript reader projects exact VCS file and immutable tree digests, validates the candidate's unit manifest, and enumerates method authority, dependency, and activation differences. A typed Natlang branch reasons through release compatibility and allowed verification. |
| Reconcile release history and active status | A scoped TypeScript port reads the assigned runtime release and one exact retained immutable build. Natlang determines whether an active or retention claim is supportable, or whether waiting is reasonable. It never calls an activation or rollback operation. |
| Resolve local dossier scope | Natlang compares the retained owner decision with the exact unit, candidate tree, requested local output, and previous build when applicable. A hard scoped service can stage one read-back scratch dossier only while those bindings still hold. |
| Verify independent world and trajectory outcome | Model-free System Testing reads package and runtime evidence anew, checks exact scratch bytes and unchanged protected heads, and the Host exporter joins those raw observations to the actual installed child and trajectory calls. |
