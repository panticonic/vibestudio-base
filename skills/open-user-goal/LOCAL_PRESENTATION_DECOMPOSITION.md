# Presenting current owned local evidence

| Stage | Form | Reason |
| --- | --- | --- |
| Discover and compare candidate records, including exact provenance | typed Natlang source review with narrow reads | The user's terms select an owner, period, and current or signed record. Similar labels alone do not establish authority. |
| Decide which questions deserve a visual and choose the representation | mounted visualize.preparePresentation | Reuse the installed planner, section chooser, availability, prop extraction, and factual readback stages. |
| Present, retry after a coedit, or hold | typed Natlang reviewLocalPresentation and preparePreview | The user's requested version and permissions determine whether fresh work is allowed and whether an accessible preview satisfies the goal. |
| Read exact local record bytes and compare revisions | TypeScript owned adapter | Durable file bytes are authoritative. Verify at the preview boundary and reread after rendering. |
| Render and verify accessible content | existing canonical TypeScript renderComponent and managed production MessageContent / CDP readback | Reject altered markup. The exact rendering, component controls, and accessible chart tables remain observable independently. |
| Join a final proof to the trace | Host exporter | The verifier compares complete value refs for performed discovery, reads, preview, source revision, typed outcome and renderer observations. |

The native Missions, provider, publication, visual incident recovery and renderer lifecycle paths do not implement these representation decisions. The existing System Testing presentation preview panel owns the test renderer; record body, author, approval and previous version are distinct from its private oracle. The original supplied-section presentation cases remain available for targeted coverage.
