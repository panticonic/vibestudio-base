# Generate and retain an owned original illustration

The installed `image-generation` system suite's `native-imagegen-save-read` baseline combines durable generation with original output into semantic workspace source. `packages/harness/src/tools/imagegen.ts` performs that composition. Its durable owners are `workers/images/ImagesDO` for asynchronous job/asset, `packages/harness/src/image-generation.ts` for response SSE/format checks, the image-service extension for decoded metadata, the Host CAS/retention database for original immutable bytes, and semantic workspace VCS for exact filesystem generations (including create-only and stale basis checks). The existing 24 image candidate scenarios import finished fixture assets to review; their assignments, service bindings and rendered labels are separate and preserved.

1. `generateOwnedIllustration` discovers a local brief and uses `inspectIllustrationBasis.readCurrentImagePlan` to bind current project output and retained job state. A typed `chooseIllustrationAction` weighs no action, native create, retry of the exact authorized failed/canceled attempt, or use of existing success. Do not create a second paid request for a queued/completed job, an occupied create-only output, or an unapproved reference or scope.
2. `runIllustrationJob.readNativeImageOutcome` drives the exact finite native `generate`/`retry` capability and observes actual terminal status with bounded waiting. Check the given stable request, attempt and immutable original digest. Failure, cancellation, invalid original or missing authorization holds any workspace save.
3. `retainIllustrationOriginal.writeVerifiedOriginal` asks the native VCS CAS for a create-only binary write of the exact bytes at the earlier observed working head. Independently read back staged and immutable payload bytes. Track any authorized simulated co-edit as a stale hold and preserve existing files.
4. The developer fixture is an isolated System Testing ImagesDO subclass using only a `resolveSession` transport seam and local deterministic SSE. It leaves the provider's credential policy, production generation parser, store, decoded metadata, native job lifecycle, running installations and normal client resolution intact. It does not read credentials or open any network connection. A no-fixture call fails closed. Test action and private exact test evidence are never included in the model prompt.
5. Native replays use the real ImagesDO worker, real retained blob files/SQLite, real metadata decoding, native semantic VCS and exact original checks. Source transport injects the local CAS, RPC and alarm-driver seams. This verifies production protocol handling and persistence with test bytes; image quality and the external generation service require separate real execution and remain outside this cohort.
