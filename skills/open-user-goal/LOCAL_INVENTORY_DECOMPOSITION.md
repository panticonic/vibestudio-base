# Choose a local model using current inventory

The user describes a continuation, a new task, or an audit. The program
identifies the current local workload docket and determines its candidate
order, tool requirements, context budget, and whether to retain the prior
conversation.

| Work | Natlang stage | Exact Vibestudio mechanism |
|---|---|---|
| Find the user’s workload | Select and read the exact current workload docket. | Scoped read of the local retained record. |
| Interpret constraints | Translate the user’s requested capability, context and continuity into a typed comparison. | Candidate references and documented labels come from the docket. |
| Decide readiness | Call the installed local model comparison hierarchy for all authorized candidates. | Actual local model extension inventory, including absent and unready rows. |
| Report the handoff | Return the exact eligible handoff or explain the missing requirements. | Independent reread of the same inventory and unchanged workspace. |

Only the read-only inventory capability is bound. The model may recommend an
exact continuation; the test does not start, download, or delegate to a model.
