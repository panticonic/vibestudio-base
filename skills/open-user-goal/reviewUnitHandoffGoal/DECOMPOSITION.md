# Review a local workspace unit handoff

The caller supplies an open request. The installed unit, current candidate, protected main, retained lifecycle, and local mutation authority come from independent owned context. Source validation and exact icon artwork do not establish runtime activation or build verification.

| Decision or operation | Implementation and reason |
| --- | --- |
| Match the request to one installed unit and identify the requested boundary | Typed `chooseUnit` resolves the requested unit and separates manifest, icon, and joined handoffs. Ambiguity and unavailable units have explicit read-only dispositions. |
| Read the chosen unit | The exact service selects one discovered repository, pins its VCS state, gives the latest scoped extension and icon operations and returns the caller's read/write grant. Service-side ownership is independent of any semantic permission inferred from the request. |
| Review the manifest and lifecycle | Installed `workspace-unit-design/reviewWorkspaceUnit/reviewLiveExtensionDesign` interprets actual working and protected-main validator receipts. `reviewDesign` determines which part of the user's question is answered and whether the candidate is suitable for a subsequent local identity edit. Extension status and build observations must match the exact source anchor before supporting lifecycle claims. |
| Choose a visual identity and its disposition | `reviewIdentity` passes the user's requested visual meaning and precise edit boundary to the installed `workspace-dev/natlang/prepareUnitIdentity`. Its typed hierarchy chooses intent, resolves the exact catalog entry, observes current icon and digest, and checks the working-only compare-and-swap change. |
| Compose a review with intact evidence | `completeHandoff` reports the selected unit, observed revision, native design and identity results, and a grounded conclusion. It holds if protected-main or working evidence changed, report authenticity failed, or the requested effect is outside the qualified operation. |
| Prepare owned fixture and prove the result | System Testing drives real native VCS, manifest validation, and icon preparation/staging. Independent reads confirm unchanged protected main, exact source and artwork digests, allowed file effects, and preserved unrelated metadata and builds. Synthetic settings define input state for verification. Reference and negative tests distinguish source evidence from runtime or build claims. |

Existing `workspace-live-unit-design` uses `bindExtensionDesign` and the production unit-manifest validator for a single preassigned extension. Existing `workspace-live-unit-identity` uses `bindUnitIdentity` and `setUnitIcon` for a single preassigned visual alternative. Their case IDs, scripts and decks remain separate. `open-unit-rollout` prepares source repairs and current build/check receipts, then may commit when authorized. `extension-dossier` inspects release versions, method deltas, build artifacts and rollback evidence. This family covers the design and identity handoff across alternatives and current draft authority, including whether a reviewed manifest can support a cosmetic edit and what the effective lifecycle evidence really says.
