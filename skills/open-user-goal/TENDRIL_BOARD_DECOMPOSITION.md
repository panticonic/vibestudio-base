# Present and reconcile an owned Tendril board

The user describes what the board should show or survive. The entry accepts
only that goal. A scoped current board record supplies the local controls and
authorized layouts. The model creates a plan and calls the installed Tendril
workflow.

| Work | Natlang stage | Exact boundary |
|---|---|---|
| Identify the board | Match the named intention to one current owned presentation ticket. | Read the bounded ticket and distinguish its archive. |
| Plan the effect | Infer field values, exposed controls, an ordered review or rollback where requested, and independent inspections. | Portable typed values and installed layout/control catalog. |
| Present and operate | Use the installed presentation and per-step hierarchy, checking each actual observation before proceeding. | Native headless renderer, CDP readback, persisted Tendril state, and actual Build V2 history. |
| Report the verified result | Return the exact plan and immediate observations, including rollback if applicable. | Separate fixture oracle binds the board, device, durable values, rendered values, revisions, and build receipts. |

The owned fixture accepts effects for its assigned board and local presentation.
The template program decides how to translate the user's goal into that
installed workflow. Existing authored assignments keep their exact request and
legacy execution path.
