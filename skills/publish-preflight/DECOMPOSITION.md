# Publication and visual preflight

The workflow reviews a caller-assigned static panel artifact before publication or while reconciling an existing provider operation. It works from Vibestudio's website package, a consistent panel-document capture and a host-journaled operation. The caller owns every effect. The program receives an evidence projection that excludes credentials, document text, unreviewed URLs and source bytes.

| Responsibility | Owner |
| --- | --- |
| Read the canonical package, panel snapshot and journal | The caller obtains website artifacts through packaging, pairs a panel observation and snapshot, and passes receipts to the TypeScript binding. |
| Bind artifacts to reviewed source and enumerate public visibility | Exact projection checks manifest identity, exact file digests, approved paths and HTML shell. A typed artifact subtree interprets blockers for the intended audience. |
| Verify a rendered presentation can support the requested public story | Exact projection binds panel identity and reports declared text probes. A presentation subtree judges whether that evidence supports the required review and uses the observations to choose a response component. |
| Reconcile preview and production at the declared destination | The publication subtree checks exact provider, destination, environment, artifact and journal identity. It separates accepted submission from verified public readback. |
| Decide the next reviewer action and communicate it | The common root integrates the independent typed checks. Verification outside the workflow compares exact dispositions, required blockers and supporting receipts. |

Use a visual only when it helps the reviewer follow several gates, compare alternatives or understand evidence over time. The report carries a typed component choice. Existing Vibestudio response rendering handles the component. A captured document establishes the specific observed text and controls; it does not certify usability at every viewport.

## Re-review a publication candidate

A prior immutable package, its reviewed destination, and a current exact
source reference establish the subject of this workflow. The native website
packager supplies the current build, public manifest, and per-file digests.

| Responsibility | Implementation |
|---|---|
| Read the current exact source through the website build path | TypeScript binding |
| Compare paths, byte counts, and digests without exposing artifact bytes | TypeScript inventory diff |
| Separate a destination change from a public content change | Natlang destination and change assessment |
| Describe whether the entry, public manifest, and delivered resources changed | Nested Natlang impact assessment |
| Decide whether to retain the review or obtain another review | Natlang decision |

A retained review describes the same artifact and destination. The workflow
leaves any later publish or provider reconciliation to its caller.
