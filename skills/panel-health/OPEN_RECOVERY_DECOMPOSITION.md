# Recover an owned visual surface

| Part | Implementation |
| --- | --- |
| Discover and choose the owned surface | The bound runtime reads the displayed title and audience of every available panel and verifies owner, context, source, and renderer. A typed Natlang child chooses the requested panel. |
| Assess current health | The binding uses the installed panel-health runtime for markers, console cursors, and panel identity. The existing typed assessment callable interprets this evidence against the surface's retained requirements. |
| Decide whether and how to recover | A Natlang child uses the user goal, assessment, current visible affordances, and approval. It chooses a scoped visible action or a sanctioned renderer reload and replans when the old observation no longer applies. |
| Act and observe | Exact CDP code revalidates one control against the current renderer and DOM revision. Native reload retains the owned panel and build. An independently initiated runtime state change can supersede a visible control before actuation. |
| Confirm and report | Natlang reassesses each inspected view. An independent exact oracle reregisters the current target generation, checks its visible markers and fresh diagnostics, and proves unrelated panels and protected workspace heads stayed unchanged. |
