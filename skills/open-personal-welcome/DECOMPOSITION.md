# Personal first-run and Explorer recovery

The retained welcome can be displayed before credentials exist and reopening
a conversation does not resend it. Current owner rows, a source-scoped
selection, an observed tour frame and a local diagnostic completion are
different kinds of evidence. This family learns how to use them together for
first-run outcomes without invoking a provider.

| Procedure | Boundary |
| --- | --- |
| Discover setup resources | Expose the requested subset of the actual Personal onboarding catalog and persisted tour deck. Keep owner scope and sender roles explicit. |
| Reconcile the latest receipts | Natlang chooses the intended resource, selects the latest authoritative record and verifies its context, owner/sender, generation, and live meaning. Prior decisions and older welcome messages stay read-only. |
| Review first-run state | Use the installed onboarding planSetup and its owner-state and selection lambdas, with a current owned readback and the actual resolveOnboardingSelection function. Report unknown and connected-unverified separately. |
| Review a tour cue | Use the installed tour-rehearsal verifyTourStop on a retained scoped frame and the actual deck descriptor. Checking an observation opens no panel and leaves the tour unchanged. |
| Retry Explorer | With explicit permission and a current interrupted local diagnostic, call the installed explorer-probe program using its exact bounded text binding. It measures real file and blobstore readbacks, then removes its scratch file. Normal probe classifications remain visible. |
| Stage the local next step | Recheck the observed frontier and workspace revision. Stage a local signed note only for the requested scope and supported evidence. Do not resend onboarding, create a workspace, issue a grant, publish a finding, launch a first-tool chat, or connect a provider. |

The managed adapter uses owned native PubSub replay, the installed Personal
catalog, tour deck and local probe binding. Owner and frame receipts are
synthetic in the disposable fixture. Software checks use native-shaped
transport to exercise the decoder and owned file and blobstore operations,
without launching managed Vibestudio or using any model.
