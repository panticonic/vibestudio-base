# Local reconciliation and retained handoff

Start from the user's outcome. It may require examining a committed incoming revision, composing independently authorized local and incoming decisions, preserving a new desk edit, holding an unresolved approval, or retaining quotable evidence of the settled revision.

## Product call tree

1. A Natlang child discovers the owned project, active authorization window and required evidence destinations. It chooses whether a local integration is warranted and which evidence must precede that decision.
2. A typed reconciliation child orchestrates the real assigned workspace service. It compares local current files and the incoming intent, plans valid per-coordinate actions and exact source edits against an observed head, and checks the resulting state. Revision changes require a fresh observation and renewed policy decision.
3. A typed handoff child selects the relevant exact observed file lines and ties the resulting scratch receipt to a released working revision. It holds pending approvals and keeps a verified integration distinct from retained handoff evidence.
4. The joint open-goal entry returns the actual decision, native revision and optional receipt. Policy lives in Natlang. The adapter handles exact operation coordinates, native VCS state and artifact durability.

## Mechanisms and consumers

- System Testing already provisions disposable target contexts and reachable source children. Its VCS fixture creates divergent native histories. The open family supplies new owned file definitions and a separate canary repository through that fixture, preserving its historical seeds and call sites. Recent edits and window changes use the same native edit path in the owned fork.
- The Base integration binding already attests observed heads, rejects foreign files and coordinate identities, and enforces exact source text and merge decisions. The new wrappers expose and log the same native behavior with a durable authorization read and explicit stale status.
- The existing scratch handoff binding stages bounded files atomically and verifies their bytes. The retained artifact consumer gets only current assigned evidence; the scratch writer is gated on the exact verified revision and authorization window.
- The private oracle independently fetches native target and source revisions, attributable merge decisions, exact target fields, neighboring bytes and protected main. It also reads the actual scratch artifact and checks its source-line evidence or independent absence.
- The shared open-goal runner and Host exporter register the family. They expose only the user's goal, scoped services and declared operation types to execution. The scenario authoring and independent checks stay with System Testing. No public publication service enters the call tree.
