# Recover retained evidence before handing off a reconciliation

A previous local scratch record can contain a useful account of a verified setting or a stale account that looks current. Make the model find the matching records and decide from their actual source and contents.

1. The shared reconciliation callable selects whether a prior-note request needs the history path. Its typed child reads the owned history catalog and plausible records, then compares their native source identity and quoted field values against the current local and incoming views.
2. The project policy decides whether to integrate, preserve, or hold. When the named prior evidence differs from the settled working state, the current native readback is the basis for any new scratch evidence. A held window may still permit reporting from a historical record.
3. The existing installed scratch callable stages new evidence only after the live integration and exact window checks. Return the identified prior record and its relationship to current evidence alongside the actual current integration and retained artifact outcome.
4. The runtime seeds earlier scratch records from real role-specific VCS snapshots in the owned context. These files remain read-only through their typed scope. The verifier rereads their exact bytes, independently checks the relevant native working and historical facts, and proves the new artifact is present or absent. It verifies original retained records survive either decision.
