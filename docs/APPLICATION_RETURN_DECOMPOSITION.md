# Application returns

Inventory: PUBLIC_APPLICATION_RETURN_INVENTORY.json records all 116 callable source entries (118 workspace-entry bindings), their exact current definitions and named-type consumers. Archived catalogs and captures remain immutable. This inventory is evidence of existing contracts, not a claim of completed migration.

A callable returns the value its caller requested: a document, findings, answer, artifact handle, or application disposition. Observations, authority decisions and intermediate drafts remain typed internal dependencies. The native journal is the source of audit evidence. A large already-staged value is returned through native staged-answer completion; the model does not reconstruct it.

## Content project

`prepareContentProject/types.ts`: evidence, decision, scope and draft are internal typed state. Their authorization and CAS fields are needed by `confirmProjectScope`, `authorProjectDocuments`, and `finishPrivateProject`, but no external application caller needs them copied into a final report. `final.candidate.files` is the actual retained document body, already stored in the workspace. Return its stable context/repository/path/head and document paths, with the actual commit event and disposition; omit a second body copy. An explanation is not a substitute for the application value.

`open-goal-prepared-content-project-managed.ts` independently reads real source revisions, journal receipts, workspace files, privacy and commit state. It must verify the returned project handle against these observations. Old envelopes remain readable in archived verification; new qualification targets the new API and rejects invented handles. No runtime, exporter, Python decoder or vendor changes are required for this structural JSON API: they store arbitrary return values; task-specific shape interpretation lives in this verifier.

Policy remains in the hierarchical NL entry and author/review stages. The TS projection from the actual finish is exact data selection, with no authorization or quality judgment.

## Owned illustration

`generateOwnedIllustration/contract.ts`: assignment and basis are internal owned-scope and CAS inputs, decision is semantic policy state. They are not the illustration. The application value is the real native job and verified original plus its saved/stale receipt; retain outcome and saved. The native managed verifier already observes basis, transport, original bytes and workspace independently; only its final value comparison must project the new application result. Its diagnostic output may retain those observations without asking the model to repeat them.

## Development audit

`reviewDevelopmentAudit/contract.ts`: assignment, observed pair and choice are internal discovery/selection state. The requested audit findings are the selected run identity, assessment (including decisive journal sequence findings) and actual keep receipt. `open-goal-development-audit-managed.ts` owns the before/after native runs, read journal and paged cursors; those independently prove scope/evidence/transition instead of comparing copied observations. Qualification rejects a foreign returned run identity and an invented assessment while preserving native wrong-scope/stale-approval probes.

## Coordinated documents

`open-coordinated-revision/types.ts`: initial, initialAuthority, plan, first, updated, updatedAuthority, reconciled, final are internal reconciliation/CAS state. Readback files contain retained document bodies; consumers need their path/version handles and actual head, with the semantic final disposition/explanation. `reviseCoordinatedDocuments/result.ts` projects those fields exactly. The native verifier checks its recorded discovery snapshots, attempts/drafts/basis, race state and actual final bytes directly. It verifies returned document handles and disposition independently, including an invented-document negative. Semantic authority prose is no longer revalidated by requiring the model to reproduce its internal report; native unauthorized writes and wrong content still fail exact atomic-basis/content/private-main checks.

## Existing domain values retained

* `answerWorkspaceQuestion.nl:12` requests the answer, actual citation paths/versions/excerpts and unresolved questions. Every `WorkspaceAnswer` field (`types.ts`) is an application answer, not an execution log. No input snapshot or hidden authorization state is returned.
* `investigatePublicQuestion.nl:11` returns the research hierarchy's grounded answer. `ResearchGoalReport.question` identifies the research question; `status` describes support; `statements` are the requested findings with citations; `notRead` names evidence gaps; `rejected` summarizes unsupported source candidates. These are research findings. `reviseFromPublicResearch.nl:11` consumes the findings to decide whether a document change is supported; `reviseWorkspaceDocument.nl:13` passes those findings into semantic revision policy.
* `answerFromAssignedPublicSources.nl:12` returns `decision` (supported/held) and the exact installed `CitedBrief`, the actual requested answer. Source assignment is internal (`selectAssignedSources`, `publicBrief.bind`) and is not duplicated in the result. The brief's support and unsupported findings are requested domain findings.
* `reviseWorkspaceDocument.nl:16` returns the actual verified document path/version or a blocked reason. `WorkspaceEditReport.status/path/version/reason` are application state/handles. Original observations, proposal and reconciliation are already internal.
* `reviseFromPublicResearch.nl:11-13` returns `ResearchRevision.research` (the requested factual findings with source citations, also supplied to the editor) and `revision` (the actual edit handle or null when support is insufficient). Both values serve the combined research-and-edit request; no workspace before-image or policy trace is returned.

## News evidence and editorial packet

`NewsEvidenceReport` remains meaningful internal state: plan selects exact owned scope; readers/schedule/briefing include model-facing observations and semantic findings; sources include verified full source bytes for consumers. The public `workOnNewsEvidenceGoal` now calls the domain-specific `reviewNewsEvidence` hierarchy and returns `NewsEvidenceResult`: topic, action and explanation identify the requested finding; readers, schedule and briefing are review findings without repeated inputs; sources are actual article citation handles; handoff is the retained private note. Child-scope mounts move with the internal hierarchy. `prepareNewsEditionReview` uses that internal review directly to ground the packet.

The outer `NewsEditionReviewResult` returns its editorial plan findings, actual packet receipt and attribution. Desk is input authority, news is child execution state, and presentation is the staged artifact's body: none needs duplicating in the outer application return. The native oracle obtains the actual presentation from the successful native stage call and verifies its exact bytes; its News verifier reconstructs observations from real recorded reader/source calls. Missing reads, source mismatches, wrong authority/cadence, private boundary changes and forged citation handles still fail. Read-only paths use native reference findings over those actual observations rather than requiring a second model copy of the child result. The original full internal verifier remains the authority for stage admission.
